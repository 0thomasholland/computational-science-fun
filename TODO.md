## critical_cell (Fortran BTW sandpile)

### Science / Correctness

- [ ] **Root version: wrong toppling threshold.** `grid%cells(i,j,k) > 6` means a cell at exactly 6 grains never topples — should be `>= 6`. The 2D/3D subdirs already use `>= 4` / `>= 6` correctly. (`grid_module.f90` lines 64, 92)

- [ ] **In-place toppling breaks synchronous BTW dynamics.** The sweep iterates over cells and immediately writes to neighbours, so later cells in the same sweep see updated values. Canonical BTW uses a copy buffer for "simultaneous" toppling. The avalanche *size* and *time* distributions (the actual SOC observables) are affected. Fix: compute all changes into a delta array, then apply. (`grid_module.f90` redistribution loops in all variants)

- [ ] **Iteration counter is overwritten.** Inside `redistribute_cells`, `grid%iteration` increments each avalanche sweep. Then `main.f90` overwrites it with the outer loop counter. The `#D` frame numbers in output are therefore unreliable and can collide across avalanches. (`2d/main.f90` line 41, `3d/main.f90` line 44)

- [ ] **`random_seed()` with no argument is implementation-defined.** On some gfortran versions this gives the same sequence every run. Use `random_seed(size=n)` + `random_seed(put=[clock-based entropy])` for reproducibility control. (all `grid_module.f90` files, init sections)

- [ ] **Visualiser frame numbering is off by one** (`3d/visualise.py`). States are appended before the diff is applied, so frame `i` shows the state *before* diff `i`. The title `f"Iteration {frame + 1}"` masks this. Append after applying each diff.

- [ ] **Root visualiser normalisation hardcoded for wrong range** (`visualise.py` line 86). `(values - 4.0) / 2.0` clips for 3D cells that can reach 7+. Use log-scale normalisation as in `3d/visualise.py`.

### Performance

- [ ] **Whole-array `prev_cells = grid%cells` copy in `write_grid_diff` on every redistribution sweep.** For nx=ny=2000 this is a 16 MB copy per sweep × hundreds of sweeps per avalanche. Track changed cells in a list instead. (all `write_grid_diff` implementations)

- [ ] **`check_critical` in the multithreaded variant scans the full grid even when a critical cell exists.** The serial version returns early on first hit. Restore early-exit (OpenMP `cancel` directive or flag-based loop). (`multithreading/grid_module.f90` lines 127-142)

- [ ] **`write_grid_diff` I/O loops are serial inside the multithreaded variant.** The inner `do i / do j` loops over 4M cells are single-threaded. Add `!$omp parallel do`. (`multithreading/grid_module.f90` lines 218-237)

### Code Quality

- [ ] **`mod(iteration, max_iterations/20)` crashes if `max_iterations < 20`** (integer divide-by-zero). Guard with `max(max_iterations/20, 1)`. (`2d/main.f90` line 48)
- [ ] **No tests.** SOC scaling laws (power-law avalanche distribution, exponent τ ≈ 1.21 in 2D / 1.27 in 3D) could serve as statistical regression tests.
- [ ] Add `-fcheck=bounds` to debug Makefile targets.
- [ ] **3D visualiser `vmin/vmax` computation materialises all frames in RAM** (`3d/visualise.py` lines 73-74). For large grids this is GBs. Use `max(g.max() for g in grid_states)` instead.
- [ ] OpenMP `reduction(.or.:redistributed)` requires OpenMP 4.5+ — document minimum gfortran version.

## seismic-wave-modeller (Rust 2D elastic FDTD)

### Science / Correctness — Critical

- [ ] **Source injects only on the trigger step — effectively a delta-function, not a Ricker wavelet.** (`simulation.rs` lines 425-437). `apply_sources` is guarded by `should_apply`, which is only `true` on the one step when a source crosses its trigger threshold. Subsequent steps of the Ricker pulse are never injected. Fix: call `apply_sources` whenever any triggered source is still within its pulse window (`current_time - trigger_time < 3.0 / frequency`).

- [ ] **Leapfrog ordering is wrong.** (`simulation.rs` lines 440, 443). Current order: `update_stresses` then `update_velocities`. This means `update_velocities` uses stresses already advanced to `t+dt`, not `t`. Correct leapfrog order for stress-velocity formulation: `update_velocities` (using σ at t), then `update_velocities` (using v at t+½dt) — or equivalently swap the two update calls and verify initial conditions are consistent.

- [ ] **Potential energy computation uses strain rate (`∂v/∂x`) instead of strain (`∂u/∂x`).** (`simulation.rs` lines 507-533). Current formula gives units of power, not energy. Energy balance plots are meaningless. Fix: compute PE from stresses alone via `PE = σ:S:σ / 2` where S is the compliance tensor, which requires only the stress fields.

- [ ] **Ricker wavelet starts at `tau = 0` with amplitude = 1 — a step-function onset.** High-frequency artefacts alias on the grid. Standard fix: shift the wavelet so it starts near zero, i.e. use `tau = t - trigger_time - t0` where `t0 ≈ 1.2/f`. The `source_t0` value is already computed in `SimulationParams::new` but passed as `trigger_time` rather than as a wavelet time-shift.

- [ ] **Ricker normalisation formula and comment are wrong.** (`simulation.rs` lines 49-59). Comment claims "peak at `arg = 0.5`" — incorrect, peak is at `arg = 0`. The factor `0.75 * π * f²` makes amplitude scale as `f²`, so high-frequency sources are artificially stronger. For a unit-amplitude Ricker, remove the normalisation or use `1.0`.

- [ ] **2D CFL condition is missing the `1/√2` factor.** (`simulation.rs` `check_cfl`). The 2D stability limit is `dt ≤ dx / (vp × √2)` for equal grid spacing; the 1D formula `cfl_safety * dx / vp` over-estimates the stable dt by `√2`. With `cfl_safety = 0.5` this is safe by accident; any `cfl_safety > 0.707` will be unstable. Fix: multiply denominator by `√2` for the 2D case.

- [ ] **4-point harmonic mean of `μ_xz` is computed pairwise, which is wrong.** (`materials.rs` lines 124-126). `H(H(a,b), H(c,d)) ≠ H(a,b,c,d)`. For heterogeneous media this gives incorrect S-wave speeds at staggered-grid shear modulus points. Fix: `4.0 / (1.0/m1 + 1.0/m2 + 1.0/m3 + 1.0/m4)`.

### Science — Minor

- [ ] **All four boundaries are rigid walls (`v = 0`).** Real seismic simulations need absorbing boundaries (PML or sponge) to prevent reflections. Noted in comments but should be prioritised — the rigid-wall reflections dominate the wavefield after one crossing time.

- [ ] **Free-surface boundary is not implemented.** The surface boundary should enforce `σ_zz = σ_xz = 0` (traction-free), not zero velocity. This is the correct physical condition for seismic modelling with a ground surface.

- [ ] **Source is an explosive isotropic pressure source** (adds equal amounts to `σ_xx` and `σ_zz`) — only excites P-waves. Document this. Adding a force-source or moment-tensor option would allow S-wave excitation.

- [ ] **Source amplitude not scaled by `dt`** — effective source strength depends on time step size, making results non-reproducible across different `dt` values.

### Performance

- [ ] **"Parallel" stress/velocity updates allocate a `Vec<(usize, usize, f64, f64)>` of ~640k tuples every timestep** (`simulation.rs` lines 691-748, 759-806). For nx=nz=800, this is ~20 MB allocated/freed twice per step. Use `ndarray::Zip::par_for_each` or in-place parallel updates with disjoint row ownership instead.

- [ ] **Visualisation draws one `Rectangle` per grid cell via `draw_series`** (`visualisation.rs` lines 69-85). For an 800×800 grid this is 640k draw calls per frame. Use a pixel buffer / `BitMapElement` instead.

- [ ] **`visualise_field` clones the entire field array each frame.** Pass `&Array2<f64>` instead.

### Code Quality

- [ ] **No tests** — `tests.rs` is empty. Add: (1) homogeneous P-wave propagation speed check; (2) energy conservation check for a closed domain; (3) Lamb's problem against analytic solution.

- [ ] `use ndarray::Zip` imported but unused — remove. (`simulation.rs` line 5)

- [ ] `SimulationParams::new` is dead code — never called from the main execution path.

- [ ] `plot_p_and_s_overlay` sort uses `.partial_cmp().unwrap()` — panics on NaN (which will occur if the simulation goes unstable). Use `.total_cmp()` (Rust 1.62+) instead. (`visualisation.rs` line 117)

- [ ] `config.rs` line 102: use `ceil()` instead of `round()` for `compute_nt` to ensure simulation reaches `total_time`.

- [ ] Terminal output in `plot_field` (`visualisation.rs` line 88) prints one line per frame — 9000 frames = 9000 terminal lines. Suppress or use a progress bar.

- [ ] No save/load checkpoints — long simulations cannot be resumed.
